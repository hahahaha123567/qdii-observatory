# 部署与运行

## 数据流

Actions 恢复状态 → 按交易日采集 → 保存状态与原始响应 → 构建静态站点 → 发布 GitHub Pages。

发布包只包含网页资源和 market.json，包含公开行情及其来源标识。SQLite、原始响应、日志不放入站点。首次状态来自 seed/state.tar.gz，后续从 market-state Release 的 state.tar.gz 恢复。启动包行情截至 2026-11-09；实际净值日期及参考行情日期在数据中分别保留。

状态包包含 SQLite 一致性备份、市值/境外参考快照及每只基金最近净值原件，确保恢复后仍能解析分红。完整采集原件按月保存到 market-raw-YYYY-MM Release，每次工作流新增独立压缩包；Actions artifact 另保留90天，方便排障。源码分支不提交日常数据库更新。Release 数据与源码可见性一致；本项目只允许公开行情。

迁移前完整历史原件已复制到本地 raw/market/qdii，旧 finance 原件仍保留。启动包只包含运行所需的最近净值原件，不代表所有历史原始响应；如需云端保留迁移前完整原件，可手动压缩该目录并上传到归档 Release。

## 调度与失败

UTC 12:35 / 22:35 执行，对应北京时间20:35 / 次日06:35，覆盖国内收盘与美股完整日线。代码独立按上海、纽约当地日期判断各自交易日，休市跳过；冬夏令时均在美股正常收盘后执行。交易日历目前覆盖2026年，跨年前须补充 config/qdii_trading_calendar.json。

GitHub 的定时调度可能延迟或漏跑；公开仓库长期无活动时定时工作流可能停用。可手动运行补采。页面显示实际行情和净值日期，不以工作流执行时间冒充数据日期。

目录刷新与已有标的更新分别处理：每次仍尝试发现产品；刷新失败时不修改目录，沿用数据库中 active=1 的已确认基金继续采集，不重新启用已停用产品，也不猜测新增产品身份。新产品发现等待下一次刷新成功。没有可用的已确认目录时仍返回非零并停止国内行情与净值更新。

沿用目录且行情与净值全部成功时，runs.status 为 degraded，runs.error 保留目录错误；命令摘要返回 catalog_error，discovered 为0，succeeded / failed 记录实际标的采集结果。网页提示目录刷新失败及沿用目录，允许构建发布新行情。目录恢复后自动回到正常发现流程。状态与错误随 market-state 保存，方便排障。

行情、净值、市值或境外参考采集错误仍返回非零，工作流保存已完成的状态和原件后失败，保留上一版线上站点。沿用目录期间标的采集失败仍记为 partial，不因降级而忽略。人工修复后重新运行即可。运行串行化，避免两个任务覆盖同一状态。首次采集失败不会发布启动包冒充更新成功。

若 market-state Release 存在但下载失败，工作流停止，不静默退回历史启动包。删除或损坏该 Release 后需人工恢复备份；seed 仅提供初始历史。不要删除自动维护的 Release 或标签。归档增长占用仓库存储，应按 GitHub 当前政策管理。

Pages 必须先在 Settings 中选择 GitHub Actions 作为发布源。项目已在本地构建、状态恢复及测试中验证；实际远程 Actions 权限、上游对云端IP的可用性和 Pages 发布须以首次云端工作流结果为准。

## 本机任务迁移

原 finance 的 macOS 本地定时任务与网页服务迁移到本项目路径，继续使用8876端口。在云端部署成功后，可按需停用本地每日采集，避免重复采集：

```bash
launchctl bootout gui/$(id -u)/local.finance.qdii-update
```

网页服务可以继续作为本地离线查看方式。重新安装命令仍为 python3 scripts/qdii_market.py install-schedule / install-service --port 8876。
